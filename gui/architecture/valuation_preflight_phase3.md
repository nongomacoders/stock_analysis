# Phase 3 valuation preflight

`valuation_preflight.py` evaluates typed `FinancialMetric` records through version-linked `ValuationInputCandidate` records. Candidate fields and case labels are enums. A candidate retains the source metric, selected value, period, source date, unit, segment, assumption type, selection reason, warnings, and optional override. Value selection is limited to the source value, its deterministic normalization, or a stated range midpoint unless an override is recorded.

Severity is `INFO` (display), `WARNING` (disclose), `ERROR` (base case needs an explicit override), or `BLOCKING` (semantic incompatibility cannot be overridden). Python assigns `eligible`, `eligible_with_warning`, `ineligible`, or `unresolved`. An override records the original ERROR findings, timestamp, actor, reason, replacement/input, and case; it never erases the findings or bypasses BLOCKING. An unresolved assumption remains unresolved even with an override.

Freshness compares name, commodity, operation, production stage, share basis, unit, and assumption class, then dates the newest comparable company disclosure. It reports selected/latest dates, day difference, status, and comparable metric ID. Different cost definitions, production stages, and guidance versus actual data do not replace each other. Older comparable cost and issued-share inputs receive ERROR for base use. Production growth thresholds default to 25% WARNING and 50% ERROR above comparable guidance/history; margin checks run only when comparators are supplied. Spot prices used perpetually warn. Missing commodity currency or unit is ERROR; incompatible stages or unresolved raw-unit conversions are BLOCKING.

New Gemini report generations add a machine-readable preflight to the version response/archive and an advisory report-audit warning on FAIL. They still publish the unchanged Gemini target. No new database table or valuation engine was added; the existing version response JSONB stores the preflight. A future engine must consume only eligible candidates and reject a FAIL preflight before computing DCF/SOTP. Report assumptions without a supported field are listed as unmapped; no numerical fallback is invented.

`inspect_valuation_preflight.py` regenerates the read-only Jubilee example from the surviving Phase 1 audit and source-grounded comparison fixture. Those comparison metrics are not retroactively claimed as Gemini generation inputs. The legacy target is `carried_forward`; no Python calculation reproduces ZAR1.70. The full result is `tmp/jubilee_phase3_preflight.json`, with a concise text rendering beside it. The legacy cost, 12,000t, WACC, growth and multiple remain unresolved; the old share snapshot is superseded. Roan guidance is eligible and Molefe ROM is a bull-case throughput warning rather than copper production. The published Jubilee report remains untouched.

Phase 4 should define source-backed input schedules, explicit volume conversion bridges (ROM, contained, recovered, saleable), cost and capex schedules, tax/debt and diluted-share schedules, then build deterministic DCF/SOTP functions that require a PASS preflight. Calculation outputs and target reconciliation should be versioned separately from Gemini narrative; high-upside targets should require an explicit reconciled schedule before publication.
