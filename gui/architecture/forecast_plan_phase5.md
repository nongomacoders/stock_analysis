# Phase 5 forecast workbench

The Research window now has a Valuation tab. A `ForecastPlan` is an immutable JSON snapshot in `forecast_plans`, linked to a report version and to the Phase 4 engine version. Editing a saved plan creates a new version; approval creates another reviewed snapshot. The tab labels evidence as REPORTED, GUIDANCE, MANAGEMENT TARGET, etc. It never copies Gemini suggestions into a valuation. Accepting a suggestion creates a distinct linked analyst assumption and leaves the suggestion intact.

The Forecast pane accepts explicit fiscal-year dates and case/operation/period assumptions. Python calculates ROM-to-contained-to-recovered-to-saleable output, cost bridges, WACC, terminal-value dependence, and scenario differences. Commodity and FX schedules show missing periods; no spot value is propagated forward. Cost definitions remain distinct. An advanced Engine Mapping pane accepts a typed `ValuationPlan` JSON whose metric IDs explicitly reference current-report evidence or accepted assumption IDs. This mapping is needed before the existing Phase 4 engine can calculate. The typed Phase 3 preflight and Phase 4 reconciliation still gate the result.

Plan approval and valuation publication are separate. Only a persisted approved plan can save a plan-linked valuation. It is saved as a **draft**. A calculable valuation requires separate approval and then a separate publish action. Historical Phase 4 valuations retain their existing publication state; the legacy Gemini target is display-only. Published deterministic valuations can be found by the latest `published_at` for a ticker; no report text or legacy target is overwritten.

Jubilee's historical report predates typed metric persistence. The workbench uses `gui/data/valuation_workbench_jubilee_evidence.json`, a frozen set of six company excerpts verified during Phase 4, only when no current-report metric rows exist. The file records source IDs and dates. It excludes unresolved legacy 12,000t, $5,950/t AISC, 12% WACC, 5% growth and 6x multiple. `tmp/jubilee_phase5_workbench.json` records the initial evidence-only plan and its missing inputs.

Current limitations: the Engine Mapping pane is a JSON editor, not a guided DCF/SOTP form. Annual and corporate cost items can be entered and audited, but an analyst still needs to wire the full Phase 4 engine plan explicitly. Sensitivity ranking requires calculable approved variants. The workbench displays an advisory critique prompt API but does not automatically call Gemini. The Jubilee evidence snapshot is frozen rather than a live disclosure refresh; source IDs and dates remain visible. No automatic selection of current commodity, FX, cost or ramp assumptions is performed.
